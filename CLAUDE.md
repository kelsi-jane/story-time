## Code Style & Conventions


All code is intended to be human maintained (potentially even open-source), so it must be clean, readable, and maintainable by humans. 

Pull requests should remain small, scoped features. General rule of thumb: no pull request should exceed ~20 files. If you are pushing more than that, think about the scope of the commit and see if you can break the requests into smaller logical pices that make sense.

The UI standard is strictly observed and must be adhered to with every feature (only exception is the admin page itself). All reader panels and author features must use the highly-polished minimal approach described in the aesthetic.md file. This is the golden standard. Stick to it. Remember: less is more. When in doubt, leave it out.
